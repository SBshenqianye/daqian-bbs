# 《大千智荟论坛》用户手册更新流程

> 目的：版本更新后更新用户手册时，**不重读全部代码**，而是以「上次文档修订日期」为锚点，读取该时间点之后的 git 提交与 diff，精确定位变更，据此更新手册。

## 触发

用户说"更新文档 / 更新用户手册 / 手册更新到新版本"等，即进入本流程。

## 锚点来源

- 文件：`docs/大千智荟论坛用户手册.docx` 第 6 章「文档修订记录」表
- 取表中**最新一行的修订日期**作为 git 锚点（精确到日，便于精确定位）

## 流程步骤

1. 读取手册修订记录表，记下上次版本号与修订日期（如 V1.0 / 2026-10-12）。
2. 定位上次更新文档时的提交（该日期当天最后一个提交）：

   ```
   git log --until="2026-10-12 23:59:59" -1 --format=%H
   ```

   > 若修订日期只精确到月份（如 2026-10），按当月 1 日 `--since` 起查，宁可多查再人工筛选。
3. 列出该提交之后的所有变更提交：

   ```
   git log <旧提交>..HEAD --oneline --no-merges
   ```

4. 查看变更统计与内容，重点看用户端/管理端/后端与文档相关的改动：

   ```
   git diff <旧提交>..HEAD --stat
   git diff <旧提交>..HEAD -- bbs-ui/src/views bbs-admin-ui/src/pages bbs-server
   ```

5. 结合 `docs/大千智荟论坛-需求分析-*.md`（若有新版本）与提交信息，梳理出：
   - 新增功能 → 手册补对应章节/小节
   - 功能调整 → 修改对应操作描述
   - 已下线功能 → 删除或标注不再支持
6. 更新手册正文后，同步更新第 6 章修订记录表：
   - 版本号：次版本 +1（如 V1.0 → V1.1；大改可升 V2.0）
   - 修订日期：**精确到日**（如 2026-10-12）
   - 修订说明：一句话概括本次更新点
7. 交付前按 word skill 规范执行 audit 校验与目录更新（catalogue.py），再交付。

## 注意事项

- 提交信息写清模块（bbs-ui / bbs-admin-ui / bbs-server / db）的，按模块对应到手册章节；未标注模块的按涉及文件判断。
- 只依据真实提交与代码事实更新，不凭猜测补写功能。
- 数据字典里的分值类内容（积分规则等）变更时，手册表格标注"以系统配置为准"，不逐个分值硬编码。
- 回复用户时简要说明本次更新依据的提交范围（如 `abc1234..HEAD`，共 N 条提交）。
