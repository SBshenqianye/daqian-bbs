## 二、现状核实（代码证据）

### 2.1 需求 5：帖子详情页无法区分「已删除」与「不存在」

- 后端入口：`ArticleController.getArticleById`（约 257 行）→ `normalizeArticle(articleService.queryArticleById(articleId))`。
- `ArticleServiceImpl.queryArticleById`（约 286–301 行）查询条件为 `enable = 1` 且 `articleId = ?`：
  - 已删除（`is_delete = 1`，`@TableLogic` 自动排除）→ 查不到 → 返回 null；
  - 未审核/已下架（`enable != 1`）→ 查不到 → 返回 null；
  - 记录不存在 → 返回 null。
- **即：三种情况后端返回完全一致（null），前端无从区分。**
- `Article` 实体关键字段：`enable`（是否审核通过）、`is_delete`（逻辑删除，`@TableLogic`）；`ArticleMapper.selectByIdRaw`（约 599 行调用）可绕过逻辑删除读取原始行，供状态判定使用。
- 前端 `BBSArticleDetails.vue` 的 `loadArticle`：`if (resp)` 才赋值，否则页面停留为空白标题 + 「暂无内容」，无任何提示。

### 2.2 需求 6 / 7：dashboard 计数已覆盖部分待办，缺 3 项

- 现有 `DashboardServiceImpl.getCounts`（`POST /admin/dashboard/counts`）已返回：
  `userCount / articleCount / commentCount / reportPending / appealPending / violationActive / articlePending / featuredCount`。
- 缺口（侧栏与浮动快捷栏需要的「待办」口径）：
  - **版主投诉待审**：`ModeratorComplaint.status = 'pending'`；
  - **采纳审批待审**：`Reply.adoptStatus = 1` + `Comment.adoptStatus = 1`（与 `ReplyController.pendingAdopts` 口径一致）；
  - **精华审批待审**：`FeaturedRecommendation.status = 'pending'`。
- 注意：现有 `featuredCount` 是「已设为精华」的总数（`isFeatured = 1`），**不是**精华审批待审数，不能直接复用。
- 前端 `Sidebar.vue`：`menuItems` 15 项、支持拖拽排序并持久化到 localStorage（`bbs-admin-sidebar-order`），无任何徽标。
- 前端 `Dashboard.vue`：快捷操作为普通网格（用户管理 / 帖子管理 / 举报管理 / 积分排名），仅举报一项有 `stats.reportPending` 徽标；`loadStats` 已拉取 `/admin/dashboard/counts`。

## 三、方案设计

### 3.1 需求 5：新增帖子状态识别接口 + 详情页三态渲染

**后端（改动点：`ArticleService` / `ArticleServiceImpl` / `ArticleController`）**

1. `ArticleService` 新增 `getArticleStatus(Integer articleId)`，返回状态字符串，判定逻辑（使用 `selectByIdRaw` 绕过逻辑删除）：
   | 条件 | 状态 | 前端文案 |
   |------|------|---------|
   | `selectByIdRaw == null` | `NOT_EXIST` | 「帖子不存在」 |
   | `isDelete == 1` 或 `enable != 1` | `DELETED` | 「该帖子已被删除或不可见」 |
   | 其余（`enable == 1` 且未删） | `NORMAL` | 正常渲染 |
2. `ArticleController` 新增 `POST /common/article/getArticleStatus/{articleId}`，返回 `ResultBean.success(obj=状态字符串)`。
3. **不动现有 `getArticleById`**，避免影响列表/管理端等其他调用方。

**前端（改动点：`BBSArticleDetails.vue`）**

1. data 新增 `articleState: 'loading' | 'normal' | 'deleted' | 'not_exist'`。
2. `mounted` 先调状态接口：`NOT_EXIST` → 渲染「帖子不存在」空态页；`DELETED` → 渲染「该帖子已被删除或不可见」空态页；`NORMAL` → 走原有 `loadArticle / loadComments / loadArticleFiles`。
3. 空态页：居中图标 + 主文案 + 副文案 + 「返回论坛」按钮（`router-link` 回论坛首页）。
4. 非 normal 状态：跳过评论/附件/作者信息加载，隐藏举报按钮、评论输入区与吸底栏（模板 `v-if` 控制）。

### 3.2 需求 6：侧栏未处理红点

**后端（改动点：`DashboardServiceImpl`）**：`getCounts` 追加三项计数（注入 `ModeratorComplaintMapper / FeaturedRecommendationMapper / ReplyMapper`）：

| 新字段 | 口径 |
|--------|------|
| `moderatorComplaintPending` | `ModeratorComplaint.status = 'pending'` |
| `featuredPending` | `FeaturedRecommendation.status = 'pending'` |
| `adoptPending` | `Reply.adoptStatus = 1` 与 `Comment.adoptStatus = 1` 之和（与 `pendingAdopts` 一致） |

**前端（改动点：`Sidebar.vue`）**

1. 维护 `label → 计数键` 映射：帖子管理→`articlePending`、违规管理→`violationActive`、举报管理→`reportPending`、申诉管理→`appealPending`、版主投诉→`moderatorComplaintPending`、采纳审批→`adoptPending`、精华审批→`featuredPending`。
2. `created` 与 `$route` 变化时拉取 `/admin/dashboard/counts`（处理完待办返回后数字自动刷新）。
3. 渲染：展开态在菜单项文字右侧显示红色数字徽标（`count > 0` 时）；折叠态显示右上角小红点。
4. 红点按 `label` 关联菜单项，不受 localStorage 拖拽排序影响。

### 3.3 需求 7：首页快捷操作浮动栏位

**前端（改动点：`Dashboard.vue`）**

1. 快捷操作从页面流中移除，改为**固定在页面右下角的浮动 dock**（横向胶囊条），提供收起/展开按钮，不遮挡正文。
2. 入口 = 各管理模块（用户管理 / 帖子管理 / 举报管理 / 违规管理 / 申诉管理 / 版主投诉 / 采纳审批 / 精华审批 / 积分排名）。
3. 排序规则：**有待办（count > 0）的模块在前，按待办数降序**；无待办模块按默认顺序排列。
4. 每项：图标 + 名称 + 红点数字（count > 0 时显示）。
5. 数据复用 `loadStats`（`/admin/dashboard/counts`），与侧栏同源。
6. 「数据概览」统计卡片保留原样。
