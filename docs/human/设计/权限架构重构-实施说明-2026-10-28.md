# 大千智荟 BBS 权限架构重构——实施说明

> 实施日期：2026-10-28  
> 设计依据：`docs/human/设计/权限架构重构-技术设计规划-2026-10-28.md`  
> 范围：`bbs-server`、`bbs-admin-ui`、`bbs-ui`

## 1. 落地结果概览

本次按 Phase 1 → Phase 5 渐进实施，接口路径与旧返回字段保持不变。

| Phase | 结果 |
|---|---|
| Phase 1 安全边界 | `/admin/**` 等管理接口要求 ADMIN/SUPER_ADMIN；开启方法级安全；`userType` 白名单；仅超管可授予管理员；前端 403 清理/跳转 |
| Phase 2 统一授权 | 新增 `AccountRole`、`Permission`、`AuthorizationService`、`SelfApprovalPolicy`；业务层移除 `id == 1` 超管判断 |
| Phase 3 数据范围 | 新增 `hasActiveRole`；撤销后可重新任命；采纳审批、精华推荐、文章审核/删除按板块校验 |
| Phase 4 前端同步 | 登录响应新增 `role/permissions/boardScopes`；路由/菜单/按钮按权限点控制 |
| Phase 5 清理文档 | 删除重复 `getCurrentUserId`、失效 `isModerator`；补权限文档与回滚说明 |

## 2. 关键类

### 后端

- `com.walker.config.security.AccountRole`：`USER/ADMIN/SUPER_ADMIN` 与 `user_type` 映射。
- `com.walker.config.security.Permission`：权限点枚举与角色矩阵。
- `com.walker.service.AuthorizationService` / `impl.AuthorizationServiceImpl`：`isSuperAdmin`、`hasPermission`、`canModerateBoard`、`getUserIdsWithPermission`（按权限广播通知）、`requirePermission`、`requireBoardModerator`。
- `com.walker.service.CurrentUserService` / `impl.CurrentUserServiceImpl`：统一从 `SecurityContextHolder` 获取当前用户。
- `com.walker.service.SelfApprovalPolicy` / `impl.SelfApprovalPolicyImpl`：收口自审批规则。
- `com.walker.config.security.ForbiddenException`：权限拒绝，由全局异常处理器转 `ResultBean(code=403)`。
- `com.walker.config.security.SelfApprovalException`：自审批业务规则拒绝（保留原有 500 业务错误语义）。
- `com.walker.mapper.BoardModeratorMapper#findAnyByUserAndLabel`：撤销后重新任命时复用历史记录。

### 前端

- `bbs-admin-ui/src/utils/adminStore.js`：`getRole/isSuperAdmin/hasPermission/getBoardScopes`。
- `bbs-admin-ui/src/router/index.js`：路由 `meta.permission`。
- `bbs-admin-ui/src/components/common/Sidebar.vue`：按权限点隐藏菜单。
- `bbs-admin-ui/src/api/api.js`：403 时清理非管理员登录态或跳 `/403`。
- `bbs-ui/src/utils/userStore.js`：删除失效的 `isModerator()`，`isAdmin()` 改为角色判断。

## 4. 数据库迁移

本次无破坏性 DDL，仅统一基础数据：

- `bbs_user.user_type` 空值/非法值 → `'1'`；
- 引导超管 `id=1` → `'3'`；
- `init-mysql.sql` / `init-pg.sql` 将 `user_type` 默认值改为 `'1'`；
- `upgrade-mysql.sql` / `upgrade-pg.sql` 新增幂等迁移块：`v037-auth-user-type-normalize`。

四个文件均已同步更新，MySQL / PostgreSQL 均可重复执行。

## 5. 回滚说明

- 代码回滚即可恢复旧行为；本次迁移不删除字段、不改变接口路径。
- 数据迁移只做 `user_type` 归一，回滚代码后不会阻塞旧逻辑。
- 若收紧“普通管理员不能创建/调整管理员”导致运维阻塞，可临时由超管账号操作；不建议通过直接改库绕过。
- 前端若需整体回滚，回退 `bbs-admin-ui` / `bbs-ui` 静态资源即可；旧字段仍保留。

## 6. 已知边界与后续项

- 举报、违规处理已按板块扩展：普通管理员仅可查看/处理本板块的举报与违规，跨板块或无板块归属的操作仅超管可执行；用户端“我的举报/我的违规”不受管理端范围过滤。
- 运营方案 V2 对板块管理员的职责描述为“板块帖子日常浏览筛查、精华帖初步推荐、识别灌水违规内容”，未明确授予板块级举报/违规裁决权；本次按产品确认，仅将数据范围限制在“本板块”，跨板块与全局操作仍由超管收口。
- 通知超管已改为**按权限广播**：举报 → `report:review`、版主投诉 → `moderator:complaint:review`、精华推荐 → `featured:review`、待审采纳 → `adopt:review`；不再依赖固定 `id=1`。
- `ArticleController.adminDeleteArticleByArticleId` / `auditArticleByArticleId` 已加板块范围；全量批量审核/删除仅超管。
- 前端按钮级权限优先覆盖管理员创建/提升、配置写入口；其余页面可继续使用 `adminStore.hasPermission()` 增量接入。
- 管理后台首次登录强制改密（C3）不在本次范围：当前 `is_first_login=1` 表示“仍在使用默认密码/被重置密码”，适用于所有新建或被重置密码的账号（含管理员），不是特指默认超管；普通成员晋升为管理员不会自动置该标记。
