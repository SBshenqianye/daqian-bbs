# 关键操作审计日志（C4）设计与实现说明

> 日期：2026-11-02  
> 范围：关键写操作、权限拒绝的可追溯留痕；不改变现有业务接口路径与返回结构。  
> 迁移版本：`v040-audit-log`

## 1. 目标

- 记录“谁在什么时候、通过哪个接口、对什么目标、做了什么、结果如何、为什么失败”。
- 审计写入失败只打 `warn`，不影响业务主流程。
- 密码、Token、Cookie 等敏感字段禁止落库。
- 仅超级管理员可查询审计日志。

## 2. 数据表

`bbs_audit_log`（MySQL / PostgreSQL 双份，见 `init-*.sql` 与 `upgrade-*.sql`）：

| 字段 | 说明 |
|---|---|
| `id` | 主键，bigint / BIGSERIAL |
| `operator_id` | 操作人用户 ID |
| `operator_name` | 操作人用户名冗余快照 |
| `module` | 业务模块，如 `ARTICLE/REPORT/USER/CONFIG/AUTH` |
| `action` | 操作编码，如 `ARTICLE_AUDIT/REPORT_REVIEW/USER_ROLE_CHANGE` |
| `target_type` | 目标类型，如 `ARTICLE/USER/DICT` |
| `target_id` | 目标 ID；批量操作可为 `ALL` |
| `before_json` | 变更前白名单快照（已脱敏） |
| `after_json` | 变更后白名单快照（已脱敏） |
| `request_method` / `request_path` | HTTP 方法与路径 |
| `ip` / `user_agent` | 客户端信息 |
| `result` | `success/fail` |
| `error_msg` | 失败原因 |
| `create_time` | `yyyy-MM-dd HH:mm:ss` |

索引：`create_time`、`(module, create_time)`、`(operator_id, create_time)`、`(result, create_time)`、`(target_type, target_id)`。

## 3. 记录方式

采用 **AOP 注解为主 + 白名单快照 + 显式上下文兜底**：

1. Controller 方法加 `@AuditLog(module, action, targetType, targetId, snapshot)`。
2. `AuditLogAspect` 统一收集：
   - 操作人（登录态）；
   - 请求 method/path/ip/user-agent；
   - `ResultBean.code == 200` 为成功，否则 `fail`；
   - 抛异常为 `fail`；`ForbiddenException/AccessDeniedException` 交给 403 处理器记录，切面不重复记录。
3. `AuditSnapshotService` 按 `targetType` 读取白名单字段（不读正文、不读密码）。
4. `AuditContext` 用于动态 `action`（如重置密码）与新增操作的目标 ID 兜底。
5. `AuditDataMasker` 统一脱敏并序列化。

### 3.1 为什么不用纯显式 Service 调用

- 大量业务校验和 early return 在 Controller；
- 纯显式调用容易漏记失败分支；
- 审计写入如果混入业务事务，可能随业务回滚。

### 3.2 为什么不用纯反射快照

- 会把文章正文、用户密码、身份证等带进审计表；
- 不同实体字段差异大，不可控。

## 4. 记录点

按模块覆盖：

- `ARTICLE`：审核、删除、精华设置/取消、批量审核、批量删除。
- `REPORT` / `VIOLATION` / `APPEAL`：举报审核、违规新增/取消、申诉审核、版主投诉审核。
- `ADOPT` / `FEATURED`：采纳审批、建议采纳、精华推荐、精华终审。
- `MODERATOR`：任命、撤销、编辑板块、奖励发放/取消/恢复/自动发放。
- `USER`：新增、角色变更、启用/禁用、详情更新、重置密码、限制发帖、删除/批量删除。
- `CONFIG`：字典、系统配置、标签、敏感词、轮播图、组织。
- `AUTH`：URL 级 / 方法级 / Service 级 403。

## 5. 权限与接口

- 权限点：`audit:read`（ADMIN/MODERATOR 无，SUPER_ADMIN 恒有）。
- 查询接口：`GET /admin/audit/list`，仅 `hasRole('SUPER_ADMIN')`。
- 过滤：`page/size/module/action/operatorId/operatorName/result/startTime/endTime/targetType/targetId`。
- 返回沿用 `ResultBean`，`obj = {records,total,page,size}`。
- 管理端页面：系统管理 → 审计日志（`AuditLogPage.vue`），路由 `/audit`。

## 6. 失败隔离与脱敏

- `AuditLogServiceImpl#record` 使用 `REQUIRES_NEW`，内部 `catch Exception` 只打 `warn`。
- 切面外层再 `catch Throwable` 兜底，并在 `finally` 清理 `AuditContext`。
- 脱敏 key：`password/oldPassword/newPassword/pwd/token/tokenStr/authorization/cookie/secret/idCard/...`。
- 手机号、身份证号保留后 4 位；不记录请求头、Cookie、Authorization。
- 单条 JSON 最长 64KB，`error_msg` 最长 1000 字符。

## 7. 测试

- `AuditLogServiceTest`：写入成功、写入失败不影响调用方、分页查询。
- `AuditLogAspectTest`：业务成功、业务失败仍记录、审计失败不影响业务、权限拒绝不重复记录。
- `AuditDataMaskerTest`：密码/Token/嵌套敏感字段脱敏、手机号/身份证保留后 4 位。

## 8. 已知限制

- 批量操作记录 `target_id=ALL`；文章批量审核/删除、用户批量删除、组织批量更新已补充 `after_json.affected`，其余批量操作逐步补齐。
- 新建用户已在 `adminAddUser` 后回填 `target_id`；其它“方法返回前不知道 ID”的创建类操作仍可能为空。
- 审计日志默认保留 180 天，每天 03:30 清理；可通过 `bbs.audit.retention-*` 调整或关闭。
- 自动任务（如定时发放版主奖励）目前只记录手动触发入口，系统任务本身未单独记录。
