# 权限组当前实现（2026-11-04）

> 状态：当前事实来源。固定角色基线已移除，权限组是账号权限的唯一来源。  
> 历史设计稿 `权限管理-设计-2026-10-29.md`、`权限架构重构-实施说明-2026-10-28.md`、`角色权限清单-2026-10-29.md` 中的角色矩阵仅作历史参考。

## 1. 核心模型

```text
用户
 ├── 主权限组（bbs_user.primary_group_id）  1 个
 │     ├── 决定账号身份（管理员 / 版主 / 普通用户）
 │     └── 决定数据范围（GLOBAL / BOARD_MODERATOR）
 └── 叠加权限组（bbs_user_permission_group） 0~N 个
       └── 只补充权限点，不改变身份和数据范围
```

有效权限：

```text
effectivePermissions =
  union(所有启用权限组的 grant 权限点)
  - union(所有 revoke 权限点)
```

- 不再有“固定角色基线 + 权限组覆盖”的计算。
- `bbs_user.user_type` 仅作为历史兼容/展示字段，**不参与鉴权**。
- 四个内置组 `role_super` / `role_admin` / `role_moderator` / `role_user` 是普通权限组，可编辑、可停用、可删除。
- 组编码只用于初始化、默认组回填和版主任命兜底，不是授权捷径。

## 2. 数据模型

| 表 | 作用 |
|---|---|
| `bbs_permission_group` | 权限组：编码、名称、适用端、数据范围、启用状态 |
| `bbs_permission_group_item` | 组直接保存的权限点（`grant` / 历史 `revoke`） |
| `bbs_user_permission_group` | 用户额外叠加的权限组 |
| `bbs_permission_preset` | 权限组配置快照（预设方案） |
| `bbs_user.primary_group_id` | 用户唯一的身份与数据范围来源 |

## 3. 启动迁移

`DatabaseInitializer` 在启动时执行幂等迁移：

1. 把旧 `base_role` 的角色基线物化为该组自己的权限点；
2. 清空 `base_role`，不再区分“系统角色组 / 临时权限组”；
3. `ROLE_DEFAULT` 统一归一化为 `GLOBAL`；
4. 没有主组的用户回填到已启用的 `role_user` 组；
5. 找不到 `role_user` 时不强行回填，避免把普通用户挂到管理类组。

## 4. 安全不变量

### 4.1 超级管理员组

系统必须始终保留至少一个**启用**且同时具备以下三个权限点的权限组：

- `admin:access`（进入管理后台）
- `permission:manage`（权限管理）
- `user:grant:admin`（授予/调整管理员）

只检查 `user:grant:admin` 不够：曾出现过去掉 `admin:access` 后超管无法登录、也无人能修复的事故。

### 4.2 当前账号自我保护

- 不能从**当前登录账号的主权限组**移除上述三个关键权限；
- 不能停用或删除当前账号的主权限组（如果会移除关键权限）；
- 前端在权限管理页锁定这三个复选框，并在分类全选、整体全选、清空时自动保留。

### 4.3 删除权限组

- 主组用户会迁移到 `role_user`；
- 没有 `role_user` 时，优先迁移到“全局且不带 `admin:access`”的组；
- 再找不到时置空，**不会**把普通用户迁移到管理类组；
- 有效权限的默认组回退同样跳过管理类组。

### 4.4 登录与 403

- 登录渠道 `02` 密码正确但缺少 `admin:access` 时，明确提示「该账号没有管理端访问权限」，不再误报密码错误；
- `AdminAccessFilter` 返回「无权访问管理后台」时，前端立即清理登录态并跳转登录页，避免轮询请求反复弹「没有权限」；
- 其他方法级 403 仍使用一次性的权限弹窗。

## 5. 权限点与适用端

- 权限点以 `com.walker.config.security.Permission` 为准。
- 管理端权限用于后台操作；前台动作权限用于发帖、评论、举报、上传等前台行为。
- `scope_type`（管理端/前台/全部）由勾选的权限点**自动推导**，只用于标记，不参与鉴权。
- `data_scope_type` 只有主权限组生效：
  - `GLOBAL`：可查看所有板块；
  - `BOARD_MODERATOR`：只能查看自己任职的板块（`bbs_board_moderator.status=1`）。

## 6. 管理端页面

入口：`系统管理 → 权限管理`（`/permission-groups`）。

布局：

- 左侧：权限组搜索、状态筛选、组列表；
- 右侧顶部：组名、编码、状态、数据范围、适用端、未保存提示和操作按钮；
- 右侧主体分页签：
  1. **权限点**：搜索、只看已选、分类全选、整体全选、清空、已选计数；
  2. **基本信息**：编码、名称、描述、数据范围分段选择；
  3. **叠加成员**：用户搜索添加、成员列表移除；
  4. **预设方案**：保存当前配置、展开详情、应用、删除。

交互约定：

- 切换权限组、新建、离开页面时有未保存修改确认；
- 顶部提供「放弃修改」；
- 切换组时使用淡入淡出，不整块闪烁；
- 四个默认组删除时二次确认；
- 编辑自己主组时关键权限锁定。

## 8. 常见操作

### 新建权限组

1. 权限管理 → 新建权限组；
2. 填写编码、名称、描述；
3. 在权限点页签勾选权限；
4. 选择数据范围；
5. 保存。

### 给用户分配主组

用户管理 → 编辑用户 → 主权限组。主组决定身份和数据范围。

### 添加叠加成员

权限管理 → 选择组 → 叠加成员 → 搜索用户 → 添加。叠加组只补充权限。

### 保存/应用预设

预设方案是当前组配置的快照。保存后可应用到其他组，会覆盖目标组的名称、描述和权限点。

### 删除默认组

四个默认组删除时会二次确认。删除后主组用户按安全顺序迁移；如果这是最后一个超级管理员组，后端会拒绝删除。
