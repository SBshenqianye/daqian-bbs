# 回滚命令（现场一页纸）

> 部署根统一用 `BBS_HOME`（生产默认 `/data/bbs`）。下面命令里的 `/data/bbs` 如需替换请整体替换。
> 回滚 = **改指针 + 重建容器**；`podman restart` 不够（不换文件、不重读环境变量）。

## 0. 先看清现状（只读）

```bash
cd /data/bbs
bash deploy.sh status
readlink -f current versions/latest
bash deploy.sh verify          # 有 FAIL 才需要回滚，FAIL 明细会打印
```

`status` 里的 `releases` 列表就是可回滚目标；`current.json` 的 `previous` 是上一版。

## 1. 应用回滚（最常用，1 条命令）

```bash
cd /data/bbs
sudo bash deploy.sh once rollback
```

- 自动切回 `current.json.previous`，重建 `bbs-server` / `bbs-nginx`，跑完整验证；
- 验证不通过会退出 1 并保留现场（不会二次破坏）；
- 包不会被归档，仍在 `packages/` 或根目录，便于重试。

指定版本（不用 previous）：

```bash
sudo bash deploy.sh once rollback --to 20261126_102549-291ae68
```

> 若包 `manifest.db_compat=forward-only`，rollback 会**拒绝**（旧代码跑新库结构），
> 需要 `--force`，且必须先按第 3 节恢复数据库。

## 2. 旧手册命令（**仍然有效**，不需要改写）

```bash
cd /data/bbs
ls versions/                                   # 旧版本目录都还在
ln -snf versions/<旧版本ts> versions/latest
podman restart bbs-server bbs-nginx            # 兼容链生效（current -> versions/latest）
readlink -f current                            # 确认指向旧版本
```

原因：`current -> versions/latest`、`versions/latest -> ../releases/current`，
把 `versions/latest` 改指旧目录即可让 `current` 跟着走。
恢复新布局：`ln -snf ../releases/current versions/latest`。

## 3. 数据库回滚（只有一种正确做法）

**不要**用"反向迁移"；迁移只有前进没有 down 脚本。步骤：

```bash
cd /data/bbs
ls -la backups/                                # 每次部署前自动 pg_dump，形如 20261127_093220/
DUMP=$(ls -t backups/*/bbs_*.sql.gz | head -1)

# 1) 停写
podman stop bbs-server

# 2) 恢复（会覆盖现有数据；先确认 DUMP 与要回退的时间点匹配）
gunzip -c "$DUMP" | podman exec -i bbs-postgres psql -U work_flow -d bbs
#    或者宿主机有 psql 客户端时：
#    gunzip -c "$DUMP" | psql -h 127.0.0.1 -p 15432 -U work_flow -d bbs

# 3) 起服务并验证
podman start bbs-server
bash deploy.sh verify
```

> `bbs_backup_*`（库内 schema）**不是**灾备：只保最近 3 份、与业务库同生共死、
> 只含当次迁移涉及的表。不要把它当回滚手段。

## 4. 结构迁移本身的回滚（本轮新增的东西）

迁移只做 `cp`、不删任何旧文件，所以"撤销结构"= 把指针指回去：

```bash
cd /data/bbs
ln -snf 20261126_102549 versions/latest        # 指回旧 versions/<ts>
podman restart bbs-server bbs-nginx            # 或 bash deploy.sh restart? 不要，restart 按 releases 走
```

- 不要去删 `releases/`、`scripts/`、`legacy/`（不影响运行，删了反而丢取证）；
- 旧容器配置快照在 `backups/<ts>/inspect.json`，手工重建时照抄 `podman run` 参数即可。

## 5. 自动回滚（部署失败时）

`deploy.sh` 在"切换后验证失败"时会自动执行第 1 节的动作，然后：

- 退出码 **1**；
- 打印 `[FAIL] 验证失败 → 自动回滚` 与失败项；
- 失败版本的 `releases/<id>/` **保留**（取证），包**不归档**；
- `current.json` 记录回滚后的版本，`previous` 记录失败版本。

此时人工只需：看 `deploy.sh diag` 结果 → 修包 → 重发（`--package` 同名包）。

## 6. 回滚后的验收（别只看进程起来了）

```bash
cd /data/bbs
bash deploy.sh verify
podman logs --tail 100 bbs-server | grep -iE 'error|exception' || echo "无 ERROR"
```

判据（全部 PASS 才算回滚成功）：三条指针一致、容器 `Mounts` 指向 `releases/<id>/app/...`、
挂载探针可读、`/files/...` 200、三个端点 200、`bbs_schema_version` 可查、重启计数不增长。
